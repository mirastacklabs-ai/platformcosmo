# @platformcosmo/core

## 0.1.0

### Minor Changes

- fa0bdd7: Assembly animator (schema 1.2.0, B-1): the animator plays the assembly render model. CSS keyframes per wrapper property (transform, visibility, opacity; identical tracks share one `@keyframes`, elements with the same animations share one rule) in both motion modes with zero SMIL, retimed to the camera at any `--speed`; frame, step and static outputs write the full wrapper state as attributes; reduced motion shows discrete per-step poses for specs with assembly actions; interactive Step pauses at the settled pose. Specs without assemblies, and assemblies without actions, produce the same bytes as before. The `phase1b` guard stays until B-2.
- c576f04: Phase 1b assemblies render (schema 1.2.0, B-2, lifting the `phase1b` guard together with B-1): specs with `assemblies` (plans, explode and implode actions, part paths) now validate and render in every output. PNG at `png.time` (default the rest frame) and the new `png.step` (the end pose of a step, with that step's camera), GIF and MP4 frames from the assembly animator, step and reduced-motion outputs. Build programs, racks and slots in assembly mode, close-ups and storyboards stay behind the guard until their phases land. The engine, GPU-server and box examples are in the browser matrix.
- aed9761: Assembly tree and frames (schema 1.2.0, scene only): `SceneGraph.assemblies` now carries the resolved assemblies. `count`/`pitch`/`use` expansion within the leaf and node budgets (same ids as validation), quarter-turn rotations, leaf geometry, rest boxes, per-axis frames (units, `fit`, true scale, anisotropic stud units), roles, `mates` and `inserts` inference, the below-ground lift, and rest-pose focus targets and part states for every assembly path. Specs without assemblies produce the same scene as before.
- ae2417e: Assembly validation (schema 1.2.0): shared id namespace and reserved ids, references with did-you-mean over the expanded part tree, program checks (moved-twice, stage ranges, build direction, no-op), leaf budget, template cycles and direction/distance diagnostics. Checks of step actions follow the merge guard's per-target gating.
- 971619a: MiraStack Labs brand look as the default (D51): `light` and `dark` take the brand colours, Oswald (display text) and JetBrains Mono (badges, metrics, edge labels via the new optional `font.mono` theme token) replace Inter in all four themes, and `canvas.grid` now defaults to `true` (schema revision 1.1.3). Set `"grid": false` for the old plain background.
  
  The exported `EMBED_FAMILY` value changes from "Inter" to "Oswald" (new `EMBED_MONO_FAMILY`: "JetBrains Mono"); `FontAsset`s now hold five faces (Oswald 400/500/600, JetBrains Mono 400/700). Display glyphs Oswald lacks (arrows) fall back to JetBrains Mono. Label, badge, metric, caption and legend sizes grow with the scene width so wide diagrams stay legible when shown small.
- a8ff00d: Build programs (schema 1.2.0, scene only; still gated by the merge guard): build steps resolve from `above`, `outside`, the axes and vectors with automatic distances against the parts already placed, the base, static callout groups, `view` per step (now also filled in `AssemblyStepPlan.view`), build and unbuild actions through the shared level machine, appearance and loop-start fade helpers, `assembly/build-path-blocked`, and reach bounds that cover build moves. Specs without build programs produce the same scene as before.
- ec442dc: TypeScript builder for assemblies (design §16): new exports `spec`, `assembly`, `explode`, `build` and `figure`. They produce plain spec JSON (typed by the generated spec types, no defaults, no I/O, nothing throws) that still goes through `validate`; racks, storyboards, images and steps are added through `spec()`.
- dfa3bcb: CLI wiring for assemblies (D-1): the CLI passes the `hw:`, `brick:` and `auto:` shape registry (and the `dc:` pack) to validation and render, so pack shapes and their `params` are checked with did-you-mean and `brick:` placement gives `brick/off-grid`. `build --png-step N` writes the PNG of the end pose of step N (`options/invalid-png-step`, exit 2). `validate --suggest` prints the explode program and story proposed by assemblies section 17, as text and under `suggestions` with `--json`. Core gains a generic `placement` callback (`PartPlacement`, for leaf parts and for groups with `at`/`pitch`) on `validate` and `render`, and `render` forwards `parts`. `brick:` groups off the stud grid give `brick/off-grid`. Specs without assemblies behave as before.
- 8147b91: New `@platformcosmo/core/internal` subpath for first-party helpers that were marked `@internal` on the root entry (`didYouMean`, `AssemblyPrograms`, `reassignSplit`, `rackTargeted`, `buildAssemblies`, `closeupDiagnostics`). Unstable: not public API, may change in any release. They are no longer exported from `@platformcosmo/core`. `pcosmo assets crop` gains `--scale 0.25-8`.
- 011777e: CSS `offset-path` particle motion mode: `RenderOptions.motion: "smil" | "css"` and `pcosmo build --motion css`. The css mode emits no SMIL elements (for hosts that strip SMIL but keep `<style>`); timing, phases, budgets and reduced motion match smil, and static/PNG/GIF/MP4 output is unchanged.
- 056a440: Explode programs and the step plan (schema 1.2.0, scene only): `SceneAssembly.programs` and `basePose` now carry resolved explode programs (selectors scoped to the program owner, direction presets, program-level automatic stacking in moved frames, order, stagger and overrides, labels and fade flags), `SceneGraph.assemblies.plan` carries the step plan for explode and implode actions (cumulative levels from one machine shared with validation, implicit access as a single move via the optional `ProgramLevel.only` and `ResolvedAction.accessLength`, one motion window and compression shared with figures, reported by validation), and `reachBounds` covers every pose the actions play. Specs without assemblies produce the same scene as before.
- 7ce841e: Image assets: `prepareImage` validates PNG, JPEG and SVG bytes (magic bytes, header dimensions, caps, APNG rejection, metadata stripped without re-encoding, EXIF orientation read first) and returns a hashed `ImageAsset`; `decodeImageDataUri` and `DEFAULT_IMAGE_LIMITS` are exported with it.
- 8562aa6: Levels and views in the assembly render model (schema 1.2.0, Phase 2 stays gated): one level group per close-up (`ids.level`, in the overlay layer) with its own overview, host rect, host focus and cross-fade geometry (`AssemblyLevelRender`), one view group per quarter turn (`ids.view`) with its own projection, depth epochs, tracks, ids (`__v<turn>` suffix) and viewBox (`AssemblyViewRender`), focus targets inside a close-up resolved in the level's own world, merged frame states, and real element counts across levels and views with `budget/views`. Existing output is byte-identical.
- 7538619: Levels and views in the assembly scene (schema 1.2.0, not yet wired into `buildScene`, Phase 2 stays gated): close-up instances at the reserved `<host>/closeup` path with nesting (at most 4 deep and 8 in all, `budget/levels`), size reconciliation against the host (`assembly/size-mismatch` only above 10%, uniform contain fit), focus targets and level lookup through close-up paths, and quarter-turn view scenes with `budget/views`. Existing output is byte-identical.
- 54135e3: New `@platformcosmo/parts-base`: the 14 `hw:` part shapes (board, cpu, heatsink, dimm, gpu-card, nic-ocp3, nvme-m2, e1s, psu, fan, riser, pcie-card, chassis-2u, lid) in true millimetres, with `readParams` did-you-mean. Core now also exports `partGeometryFaces`, `partPrimitiveFaces` and `halfOf`, and `didYouMean` from `@platformcosmo/core/internal`.
- 2d486b9: New `@platformcosmo/parts-brick`: the five `brick:` part shapes (brick, plate, tile, round, slope) in stud units, with a stud grid on top (studs extend `bounds` but not `depthBox`), a generic colour palette, `readParams` did-you-mean, and `checkBrickPlacement` for the `brick/off-grid` warning. Core now also exports `studGrid`, `STUD_DIAMETER`, `STUD_HEIGHT` and `partPrimitiveSilhouette`.
- f75a9d9: Phase 2 renders (schema 1.2.0, D-4a, lifting the `phase2` guard): rack programs, slot internals, close-ups (fields and `…/closeup` paths), actions on racks and slots, and build programs now validate and render in every output. Figure close-ups draw the figure in their level (each instance with its own pose, checked as a figure action), and a figure a `closeup` names is drawn only there. Levels are drawn at their own scale, a focus inside a level zooms onto that node, and frame and step outputs keep levels in the camera. Counted parts moved together share one label, a zoom widens to hold a label it would cut, and a targeted rack's devices keep their 1.1 fronts at rest. New gallery example "From the hall to the heat sink" with synthetic images, and a user guide for assemblies and close-ups.
- c855036: Assembly render model and emit (schema 1.2.0, not reachable from `validate` until Phase 1b is lifted): `RenderModel.assembly` carries the depth epochs, the one DOM order, per-copy tracks, labels and leaders, reach-bounds extents, per-step END-pose focus rects and `frameAt`/`stepEnd`. The wrapper chain is `host > clip > motion > visible > fade > part`. `createIds` now returns the whole `AssemblyIdScheme`. Specs without assemblies render byte-identically.
- 4851912: Schema revision 1.2.0 (additive): `assemblies`, `images`, `storyboards` and `figures`, step `assembly` actions (explode, implode, build, unbuild), part paths in `steps[].focus` and `steps[].set`, rack `programs`, slot `assembly` and `closeup`; plus the assembly contract types. Not rendered yet: `validate` (and so `pcosmo validate` and `build`) rejects every 1.2.0 field with `assembly/unsupported` until the phase that renders it lands. Design: `docs/design/assemblies.md`.

### Patch Changes

- a532041: Export `decodePng` and `pngSize` (8-bit RGBA PNG reader used on resvg output) for the private assets package.
- The A2-3 program planner now also resolves a rack in assembly mode (`source: "dc"`): rack and slot owners, the pack's built-in `drawers` and slot `internals` bodies through a `synthetic` option, and a cover given `drawer` leaves along its own outward normal. `AssemblyPrograms` and `reassignSplit` are exported from `@platformcosmo/core/internal` (internal API) for the DC pack. Spec assemblies are unchanged.
- fb45bc3: Figures render (assemblies track R-1): `images` and `figures` are no longer rejected as `assembly/unsupported`. A figure is an upright panel with its base image and cut-out sprites (embedded once per image, EXIF orientation applied) that move between their seated and exploded positions in explode/implode steps, as CSS in both motion modes and as exact frames for PNG, GIF and MP4. Motion arrows fade, labels with leader lines appear when parts arrive, a credits line lists image attributions, and reduced motion shows discrete per-step poses. A figure can take a step `focus`, and an explicit `pos` that overlaps other content warns (`layout/overlap`). Rendering needs the prepared images (`RenderOptions.images`); a missing one is `image/not-found`. Assemblies, storyboards and the later phases are still guarded.
- 66c8478: Figures in validate and the scene (assemblies track A2-F): image ids and references, figure parts and stages (selectors, timing, implode as the exact time reverse, step windows and compression), explode/implode actions on figures, `SceneFlatBoard`s with credits, and a did-you-mean on every figure diagnostic. Schema errors for oneOf values (assembly actions, programs, part images) now report the branch the data's own key, `kind` or type names, instead of "Not a valid ...". Figures still validate as `assembly/unsupported` until the figure renderer lands.
- 7d9f846: Icon packs added from a URL take the repository name as their id and print it with an example ref; derived names are sanitised and provider ids reserved (#52). Did-you-mean suggestions are bounded, so a 1 MB unknown key no longer stalls validation (#55).
- 9395785: Fix `pcosmo build --gif` and `--mp4` failing with `export/too-large` on default options: GIF and MP4 frames are now rendered and encoded one at a time (GIF encoder and ffmpeg stdin), so memory is bounded by one frame plus the encoded output. Limits: one frame (and a PNG) at most 256 MiB of RGBA, encoded output at most 1 GiB, and an encoder without streaming support keeps the 1 GiB whole-clip cap. Ctrl-C now stops ffmpeg and removes its temp files; a hung ffmpeg is killed after the timeout, and a wedged `ffmpeg -version` probe no longer hangs the build.
  
  MP4 output changes: the CLI now uses core's ffmpeg encoder, so mp4 is encoded at x264 crf 18 with bit-exact flags (reproducible bytes for one ffmpeg build) instead of x264's default quality. The file grows accordingly (263 KB to 355 KB on the load-balancing example); odd-sized frames are still padded with white.
